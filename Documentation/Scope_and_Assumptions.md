# Scope and Assumptions

## 1. Project Overview

This document defines the scope, assumptions, limitations, and boundaries of the simulated GRC assessment conducted for SecurePay Solutions Pvt. Ltd.

SecurePay Solutions is a fictional FinTech organization created for educational and cybersecurity portfolio purposes.

---

## 2. Assessment Objective

The objective of the assessment is to demonstrate a structured GRC approach to:

* Asset identification
* Cybersecurity risk assessment
* Security control assessment
* Risk-control mapping
* ISO 27001-based gap assessment
* Risk treatment
* Remediation planning
* Evidence tracking
* GRC reporting

---

## 3. Assessment Scope

### In Scope

The assessment covers:

* Customer-facing web application
* Customer database
* Cloud infrastructure
* Employee laptops
* Employee accounts
* Corporate email
* VPN
* Firewall
* Backup infrastructure
* Source code repository
* Identity and access management
* Vulnerability management
* Security monitoring
* Incident response
* Security awareness

---

## 4. Out-of-Scope Areas

The following activities and environments are outside the scope of this project:

* Physical data center security
* Actual production infrastructure
* Real customer information
* Penetration testing
* Vulnerability exploitation
* Detailed financial auditing
* Third-party payment processor assessments
* Legal or regulatory certification
* Formal ISO 27001 certification audit
* Business continuity testing against a real production environment

---

## 5. Key Assumptions

The assessment uses the following assumptions:

### Organization

SecurePay Solutions is assumed to have approximately 50 employees and operate as an online payment service provider.

### Technology

The organization is assumed to use cloud infrastructure, web applications, databases, corporate email, VPN, firewalls, endpoint protection, and backup systems.

### Security Controls

The security controls documented in the project are assumed to exist at the stated implementation levels.

Control statuses include:

* Implemented
* Partially Implemented
* Not Implemented

### Risk Data

All likelihood and impact ratings are simulated estimates based on the assumed business environment.

### Evidence

Evidence listed in the Evidence Register is simulated and created for demonstration purposes.

No real organizational logs, configuration files, customer records, or confidential information were used.

---

## 6. Framework Assumptions

ISO/IEC 27001 is used as the primary reference framework for the assessment.

The assessment is intended to demonstrate awareness of information security management and control concepts.

NIST Cybersecurity Framework is used as a supporting reference for cybersecurity risk management concepts.

---

## 7. Assessment Limitations

This project does not include:

* Interviews with real employees
* Physical security inspections
* Real system configuration reviews
* Production log analysis
* Penetration testing
* Vulnerability exploitation
* Independent audit procedures
* Legal or regulatory opinions
* Certification activities

Therefore, the findings should not be interpreted as an actual organization's security posture.

---

## 8. Evidence Limitations

Evidence used in this portfolio project is simulated.

Examples include:

* Simulated MFA configuration records
* Simulated vulnerability reports
* Simulated access review records
* Simulated backup reports
* Simulated security monitoring information

These examples demonstrate how a GRC analyst may track evidence during an assessment.

---

## 9. Risk Assessment Limitations

Risk ratings are based on the assumed environment and simplified likelihood × impact methodology.

Actual organizations may use:

* Financial impact calculations
* Asset valuation
* Threat intelligence
* Business impact analysis
* Regulatory requirements
* Risk appetite
* Historical incident data
* Quantitative risk analysis

Therefore, the risk ratings in this project should be treated as illustrative.

---

## 10. Compliance Disclaimer

The project represents an **ISO 27001-based gap assessment**, not an official ISO/IEC 27001 audit or certification assessment.

The project does not claim that SecurePay Solutions is ISO 27001 certified or compliant.

---

## 11. Data Protection

No real personal, financial, customer, employee, production, or confidential organizational information was used in this project.

All data has been created specifically for educational and portfolio purposes.

---

## 12. Project Classification

**Project Type:** Cybersecurity GRC Portfolio Project
**Organization:** Fictional
**Assessment:** Simulated
**Data:** Simulated
**Evidence:** Simulated
**Primary Framework:** ISO/IEC 27001
**Supporting Framework:** NIST Cybersecurity Framework

---

## 13. Final Disclaimer

> SecurePay Solutions Pvt. Ltd. is a fictional organization. This project is entirely simulated and was created to demonstrate practical understanding of cybersecurity Governance, Risk, and Compliance concepts.
